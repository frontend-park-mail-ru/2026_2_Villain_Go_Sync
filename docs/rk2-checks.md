# Проверка фронтенда для РК2

Объём: профиль, создание/просмотр/редактирование/удаление вакансий и резюме,
отклик и список соискателей. Дополнительно подключены фото в шапке и изображения карточек.
Поиск по категориям, PDF, избранное и уведомления в эту работу не входят.

## Автоматические проверки

```sh
npm ci
npx playwright install chromium
npm run lint
npm run typecheck
npm run build
npm test
```

Playwright запускает собственный сервер на порту 8001. Порт должен быть свободен.
Тесты подменяют ответы API: они проверяют поведение интерфейса и отправляемые запросы,
но не проверяют CORS, базу данных, cookies реального сервера и S3.

Покрыты:

- CSRF-заголовок, обновление токена, повтор после 401, обычный отказ 403;
- роли из `/me`, общий список откликов, письмо и переход к приложенному резюме;
- создание, просмотр, редактирование и удаление документов, отмена удаления;
- отправка отклика с выбранным резюме;
- отсутствие профиля до открытия формы и в момент отправки;
- сохранение черновика на время заполнения профиля, включая перезагрузку вкладки;
- возврат только на разрешённые внутренние страницы;
- загрузка/удаление фото и логотипа, проверка формата, обновление шапки;
- ошибки изображений и текстовые заглушки;
- отсутствие горизонтального переполнения проверенных страниц на 320, 360 и 1440 px.

## Проверка с настоящим API

Нужен backend с изменениями `fix/api-consistency`: роль в `/me`,
`GET /api/employer/applications`, `resume_id`, `company_name` и API изображений.
В CORS должны быть разрешены адрес запущенного фронтенда, credentials и заголовок
`X-CSRF-Token`. Для localhost фронт и API должны использовать одинаковое имя хоста:
cookie `csrf_token` читается фронтендом, cookies авторизации — только сервером.

После запуска API проверить под обеими ролями:

1. Регистрацию, вход, перезагрузку, продление сессии и выход.
2. Сохранение профиля, загрузку, замену и удаление изображения.
3. CRUD вакансий и резюме, включая отсутствие профиля.
4. Отклик, отказ повторного отклика, список соискателей и открытие резюме.

При выполнении этой работы `http://localhost:8080/api/health` не ответил за 3 секунды.
Проверка с настоящим API остаётся необходимой перед демонстрацией; успешные тесты
с подставными ответами её не заменяют. Бэкенд и данные его базы не изменялись.
